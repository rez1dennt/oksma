# Отправка заявок через PHP `mail()`

## Цель

Перевести формы сайта ОКСМА с SMTP-аутентификации на встроенную функцию PHP `mail()`, чтобы для отправки заявок не требовались SMTP-пароль и закрытый файл `config/mail.php`.

## Адреса

- Получатель всех заявок: `oksmaprom@yandex.ru`.
- Отправитель писем: `oksmaprom@yandex.ru`.
- Если посетитель указал email, он используется только в безопасном заголовке `Reply-To`.
- Имя отправителя: `Сайт ОКСМА`.

Адрес получателя и отправителя берётся из публичной конфигурации приложения `config/app.php`, чтобы на сайте оставался один источник контактных данных.

## Архитектура

Сохраняется интерфейс `LeadMailer` и функция `deliver_lead()`. Вместо SMTP-транспорта используется `NativeMailLeadMailer`, который:

1. принимает уже проверенные и нормализованные данные заявки;
2. формирует текстовое UTF-8 письмо через существующий `lead_email_body()`;
3. добавляет безопасные заголовки `From`, `Reply-To`, `MIME-Version`, `Content-Type` и `Content-Transfer-Encoding`;
4. вызывает встроенную функцию PHP `mail()`;
5. выбрасывает исключение, если `mail()` возвращает `false`.

В транспорт внедряется вызываемая функция отправки. В production по умолчанию применяется PHP `mail()`, а тесты используют локальную функцию-заглушку и не отправляют реальные письма.

## Обработка формы

`submit.php` больше не проверяет наличие `config/mail.php` и не загружает SMTP-секреты. После успешной серверной валидации он создаёт `NativeMailLeadMailer` с адресом `oksmaprom@yandex.ru` из `app_config()`.

При успешной передаче письма PHP пользователь получает текущее подтверждение. При отказе системного почтового транспорта сохраняется текущее нейтральное сообщение об ошибке, а техническая причина пишется только в серверный журнал.

Важно: успешный результат `mail()` означает, что локальный почтовый транспорт принял письмо, но не гарантирует доставку. Фактическая доставка проверяется после загрузки на PHP-хостинг.

## Безопасность

- Данные формы проходят существующую серверную валидацию и очистку.
- Значения заголовков дополнительно отвергаются при наличии `CR` или `LF`, чтобы исключить подмену заголовков.
- Тело письма остаётся обычным текстом без HTML.
- Пароли, cookies и CSRF-токены не попадают в письмо или журнал.
- Реальный email посетителя не используется как `From`, что снижает риск отказа почтового сервера.

## Удаление устаревшей SMTP-настройки

- Удаляется неиспользуемый SMTP-транспорт.
- Удаляется `config/mail.example.php`.
- Удаляется зависимость PHPMailer и связанные Composer-файлы, поскольку других зависимостей Composer у проекта нет.
- README и инструкция публикации обновляются под PHP `mail()`.
- Запрет на публикацию SMTP-паролей сохраняется как общий принцип безопасности, но SMTP больше не требуется для работы формы.

## Тестирование

Автоматические PHP-тесты должны подтвердить:

- получателя и отправителя `oksmaprom@yandex.ru`;
- корректную тему и UTF-8 тело письма;
- добавление `Reply-To` только при наличии безопасного email;
- отсутствие `Reply-To`, если email не указан;
- исключение при отказе `mail()`;
- отсутствие зависимости обработчика от `config/mail.php`;
- прохождение всей существующей тестовой матрицы сайта.

На хостинге выполняется одна реальная тестовая заявка. Если хостинг отключил PHP `mail()` или требует локальный доменный адрес отправителя, это будет отдельной настройкой панели хостинга, а не SMTP-паролем Яндекса.
