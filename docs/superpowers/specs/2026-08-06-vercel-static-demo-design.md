# Статическая демоверсия ОКСМА для Vercel

## Цель

Подготовить публичную демонстрационную версию сайта, которую можно открыть на Vercel и показать клиенту. Демоверсия должна позволять переходить по главной странице, категориям, товарам, документам и политике, а также пользоваться клиентскими интерактивными элементами. Рабочая отправка заявок на этом этапе не требуется.

## Источник правды

Оригинальный PHP-сайт в корне репозитория остаётся единственным источником правды и не переводится на статическую архитектуру. Его структура сохраняется для последующей загрузки на обычный PHP-хостинг.

Папка `vercel-demo/` является только генерируемым результатом. Её нельзя редактировать вручную. Любая будущая правка выполняется в оригинальном сайте, после чего экспортёр полностью пересобирает демоверсию. В коммит попадают и исходные изменения, и актуальный результат экспорта.

## Архитектура экспорта

- `scripts/export-vercel-demo.php` получает список публичных маршрутов из каталога.
- Каждый маршрут рендерится оригинальным PHP-приложением в отдельном CLI-процессе, чтобы страницы не делили глобальное состояние.
- HTML сохраняется в каталогах с `index.html`, поэтому исходные красивые URL продолжают работать без PHP.
- В `vercel-demo/` копируются только публичные ресурсы: `assets/` и `favicon.ico`.
- `sitemap.xml`, `robots.txt` и страница `404.html` генерируются отдельно.
- Перед новым экспортом удаляется только заранее проверенная папка `vercel-demo/` внутри корня проекта.

## Публичные маршруты

Экспорт включает:

- `/`;
- все `/catalog/{slug}/`;
- все `/product/{slug}/`;
- `/documents/`;
- `/privacy/`;
- `/sitemap.xml`;
- `/robots.txt`;
- `/404.html`.

Статические ссылки и изображения остаются корневыми, поэтому одинаково работают локально и на домене Vercel.

## Поведение форм

В демоверсию добавляется отдельный `demo-mode.js`. Он перехватывает отправку форм до основного обработчика, не выполняет сетевой запрос и показывает понятное сообщение о том, что заявка в демонстрационной версии не отправляется. В оригинальную PHP-версию этот режим не подключается.

## Конфигурация Vercel

В `vercel-demo/vercel.json` задаётся статическая публикация, корректная страница 404 и защитные HTTP-заголовки. В настройках проекта Vercel пользователь выбирает `vercel-demo` как Root Directory. Build Command и Output Directory не требуются: содержимое папки уже готово к публикации.

## Проверка

Автоматические тесты должны подтверждать:

- наличие всех ожидаемых экспортированных маршрутов;
- отсутствие PHP-файлов и приватных каталогов в демоверсии;
- наличие ресурсов, PDF и конфигурации Vercel;
- подключение демо-режима формы на каждой HTML-странице;
- отсутствие внутренних ссылок на несуществующие файлы;
- сохранение исходного PHP-сайта без переноса или дублирования логики.

После экспорта дополнительно выполняются существующие PHP-, JavaScript- и Python-тесты проекта и HTTP/файловая проверка ключевых страниц.

## Рабочий процесс после будущих правок

1. Изменить оригинальный сайт.
2. Запустить `php scripts/export-vercel-demo.php`.
3. Прогнать тесты.
4. Закоммитить исходники и обновлённую `vercel-demo/` вместе.
5. Отправить `main` в GitHub — Vercel автоматически обновит публичную демоверсию.
