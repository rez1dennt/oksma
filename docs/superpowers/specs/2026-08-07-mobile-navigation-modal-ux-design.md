# Mobile Navigation and Compact Modal UX Design

## Goal

Исправить мобильную навигацию сайта ОКСМА так, чтобы возврат системной кнопкой браузера восстанавливал точную позицию страницы, бургер-меню открывалось и закрывалось плавно без визуального скачка, а модальное окно заявки помещалось в обычный телефонный viewport без внутреннего скролла.

## Confirmed User Flow

Основной сценарий восстановления позиции:

1. Пользователь прокручивает страницу на телефоне.
2. Открывает бургер-меню.
3. Переходит из меню в категорию или на другую внутреннюю страницу.
4. Нажимает системную кнопку браузера «Назад».
5. Исходная страница возвращается к той же позиции, на которой пользователь открыл меню.

## Root Causes

### Lost scroll position

Текущая блокировка прокрутки переводит `body` в `position: fixed`. При этом `window.scrollY` становится равным нулю, а прежняя позиция визуально компенсируется отрицательным смещением `body`. Если пользователь нажимает ссылку в меню, навигация начинается раньше, чем асинхронное закрытие меню освобождает страницу. Браузер сохраняет в history нулевую позицию и при возврате открывает верх страницы.

### Abrupt drawer motion

Меню сначала получает `hidden = false`, а открытый класс добавляется через один `requestAnimationFrame`. Некоторые мобильные браузеры объединяют эти изменения в одну отрисовку. Начальное состояние панели не успевает попасть в отдельный кадр, поэтому переход может выглядеть мгновенным или начинаться со скачка.

### Oversized modal

На viewport `390 × 844` содержимое диалога имеет высоту около `1025px`, а доступная высота диалога составляет `812px`. Основные источники лишней высоты: одноколоночная форма, постоянная высота пустых контейнеров ошибок, textarea на четыре строки, крупные межблочные интервалы и избыточные вертикальные отступы заголовка.

## Chosen Approach

### Native browser restoration

Сайт сохраняет нативное `history.scrollRestoration = auto`. Ручное хранение координат в `sessionStorage` не добавляется: оно может возвращать пользователя к устаревшей позиции после обычных переходов и усложняет поддержку.

Блокировка страницы больше не должна постоянно фиксировать `body`. Она должна:

- сохранить текущие координаты;
- отключить прокрутку через overflow/overscroll без визуального перемещения документа;
- компенсировать исчезновение вертикального scrollbar на десктопе;
- при освобождении не вызывать `scrollTo`, если координаты не изменились;
- восстановить сохранённые координаты только как fallback, если браузер всё же изменил их.

При выборе ссылки в мобильном меню overlay синхронно приводится в закрытое состояние и блокировка снимается до выполнения стандартной навигации ссылки. Переход не задерживается ожиданием анимации.

### Deterministic drawer animation

После снятия `hidden` браузеру даются два последовательных кадра: первый фиксирует начальное состояние, второй добавляет открытый класс. Это гарантирует запуск CSS transition.

Анимация использует только `transform` и `opacity`:

- backdrop плавно проявляется;
- панель въезжает с правого края с `ease-out` из общей системы motion tokens;
- закрытие немного быстрее открытия;
- при `prefers-reduced-motion: reduce` перемещение отключается, остаётся практически мгновенное изменение прозрачности.

Во время меню сохраняются текущие accessibility-возможности: `aria-expanded`, Escape, focus trap, inert-фон и возврат фокуса на trigger при обычном закрытии.

### Compact modal layout

В модальном варианте форма получает отдельный модификатор, не меняющий большую форму в секции главной страницы.

Компактный диалог использует:

- двухколоночную сетку полей на мобильных устройствах;
- имя и телефон в первой строке;
- email и комментарий во второй строке;
- полную ширину для согласия, кнопки и статуса;
- textarea высотой примерно в две строки;
- уменьшенные, но токенизированные padding и gaps;
- пустые элементы ошибок без зарезервированной высоты; при появлении ошибки она расширяет диалог естественно;
- более короткий вертикальный ритм eyebrow, заголовка и пояснения;
- `100dvh` вместо статического `100vh` для учёта мобильной панели браузера.

Целевой normal-state: весь диалог помещается без внутренней прокрутки при viewport от `320 × 568`. Защитный `overflow-y: auto` сохраняется только для открытой экранной клавиатуры, увеличенного системного текста, 200% zoom и появления нескольких ошибок одновременно. Контент никогда не обрезается ради формального отсутствия scrollbar.

## Accessibility Requirements

- Диалог сохраняет `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, Escape, focus trap и возврат фокуса.
- Все touch targets остаются не меньше `24 × 24px`; основные кнопки сохраняют текущую высоту control token.
- Поля сохраняют видимые labels, autocomplete, ошибки через `aria-describedby` и статус через live region.
- Сетка не меняет логический DOM-порядок: Tab идёт `Имя → Телефон → Email → Комментарий → Согласие → Отправить`.
- Ни анимация меню, ни modal motion не работают против `prefers-reduced-motion`.
- При zoom или появлении клавиатуры приоритет отдаётся доступу ко всем полям, поэтому safety-scroll допустим только в этих ограниченных состояниях.

## Responsive Rules

- Проверяем минимум `320 × 568`, `360 × 740`, `390 × 844` и desktop `1280 × 720`.
- На узком экране поля остаются читаемыми и не создают горизонтальную прокрутку страницы.
- Если ширины для устойчивой двухколоночной строки недостаточно, телефон и комментарий могут занимать всю ширину через явные field modifier classes, сохраняя компактную высоту остальных строк.
- Открытие меню не изменяет `window.scrollY` и не двигает sticky header.

## Testing Strategy

### Automated tests

- Обновить unit-тесты scroll lock: отсутствие фиксации `body`, отсутствие лишнего `scrollTo`, fallback-восстановление при реально изменившихся координатах, корректная вложенная блокировка.
- Добавить unit-тест двухкадрового запуска overlay motion и проверить ожидаемую последовательность scheduler callbacks.
- Добавить render/CSS contract-тесты для compact modal modifier, двухколоночной сетки, collapsed empty errors, reduced-motion и dynamic viewport sizing.
- Полностью прогнать PHP, JavaScript и Python suites.

### Browser verification

- На мобильном viewport прокрутить страницу, открыть меню, перейти по внутренней ссылке, нажать Back и сравнить координату до перехода и после возврата.
- Измерить `window.scrollY` до и после открытия/закрытия меню; допустимое изменение равно нулю.
- Снять значения panel transform/opacity в начале, середине и конце transition, подтверждая реальную промежуточную фазу.
- Открыть modal на всех целевых viewport и проверить `scrollHeight <= clientHeight` в normal-state.
- Проверить Escape, Tab/Shift+Tab, возврат фокуса, отсутствие горизонтального overflow и console errors.

## Source and Demo Synchronization

Канонические изменения вносятся только в `assets/`, `templates/` и тесты PHP/JS. После проверки запускается `php scripts/export-vercel-demo.php`, чтобы `vercel-demo/` получила те же CSS и JavaScript. Сгенерированная папка вручную не редактируется.

## Out of Scope

- SPA-навигация и клиентский router.
- Сохранение позиции между новой вкладкой, новым сеансом или обычным повторным открытием URL.
- Изменение состава полей формы или серверной отправки.
- Полный редизайн header, формы главной страницы или цветовой темы.
